## 2. Сравнение способов доставки

| Вариант | Суть | Плюсы | Минусы | Оценка |
|---|---|---|---|---|
| **PWA** | Манифест + service worker, «Добавить на главный экран» | минимум кода, нет магазина, мгновенные обновления | не публикуется в RuStore как приложение; уведомления и «нативный» вид ограничены | 1 спринт, как база для остальных |
| **TWA (Bubblewrap/Trusted Web Activity)** | APK, который открывает `https://app.ai-pets.ru` в Chrome Custom Tab | переиспользует весь веб, быстро; не нужен дубль UI | нужен `assetlinks.json` на домене; зависит от Chrome на устройстве; слабый доступ к нативным API (push, хранилище) | 1–2 спринта, запасной вариант |
| **Capacitor (рекомендуется)** | WebView-обёртка React-приложения + нативные плагины | один код UI; плагины для Secure Storage, Push, Deep Links, Filesystem; можно собрать AAB для RuStore | нужен Android SDK/Gradle, keystore, поддержка обновлений веб-ассетов | 3–4 спринта до витрины |
| **Kotlin Compose нативно** | Полностью отдельный UI | максимум возможностей и производительности | дублирование UI/логики, дорого и медленно | не сейчас |

**Рекомендация:** сначала PWA-база (быстрый выигрыш и меньше риска), затем
Capacitor как основной путь в RuStore; TWA держать как fallback, если
Capacitor упрётся в модерацию или сроки. Kotlin — отдельная инициатива после
продуктовой проверки гипотезы.

### Проверенные требования к файлу и версии

- [x] Поддерживаются **APK и AAB**. APK: ≤ 5 ГБ, подписан цифровым
      сертификатом, уникальное имя пакета; каждая новая версия — с бóльшим
      номером и той же подписью. AAB: ≤ 5 ГБ, подписи загружаются
      **отдельно** перед файлом.
- [x] Загруженные и обработанные файлы хранятся **14 дней**; если за это
      время не отправить версию на модерацию, они удаляются.
- [x] В одну версию можно положить несколько файлов (основной, для
      Huawei/Honor с HMS, для ТВ, с другой подписью). Если есть подпись
      Google Play и собственная, основным файлом следует выбрать файл с подписью
      вне сервисов Google.
- [x] Подпись: хранить локально и в секретах CI; использовать **один
      сертификат для всех версий**. Отладочная подпись и
      `android:debuggable=true` — признаки, из-за которых модерация может
      отклонить сборку. При утере ключа смена подписи — через
      `support@rustore.ru` со снятием всех версий в архив.
- [x] `minSdkVersion` подтягивается из манифеста (если не указан — 1);
      `targetSdk` отдельно в прочитанной странице не регламентирован,
      но с сезоном требования могут ужесточаться — перепроверить перед
      первым билдом в Консоли.

## 7. Пояснения и решения по открытым вопросам

### 7.1. Владелец аккаунта — решено

Андрей Н. (Андрей Никифоров), VK ID, физическое лицо. Права владельца в
консоли есть. Юридическое лицо для публикации не требуется: правила RuStore
допускают физических лиц и ИП.

### 7.2. Keystore — решено, хранитель вы

Keystore — это файл (`*.jks`/`*.keystore`) с закрытым ключом, которым
подписываются APK/AAB. Android сравнивает отпечаток сертификата при
обновлении: **если потерять ключ, приложение нельзя будет обновить** —
потребуется письмо в `support@rustore.ru`, архивация всех версий и повторная
загрузка сборок (см. раздел 3).

Что хранить у вас:

- сам файл keystore и пароль keystore;
- alias ключа и пароль ключа;
- офлайн-копию (например, зашифрованный архив на внешнем носителе).

В CI это секреты, не файлы в Git: `ANDROID_KEYSTORE_BASE64`,
`ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.
В репозиторий попадать не должно ничего, включая debug-ключ. Начиная с
первой публикации используется один и тот же сертификат.

### 7.3. Что такое push в MVP и нужен ли он

Push — это **системное уведомление на телефоне** (шторка), даже когда
приложение закрыто. Сейчас у нас работают уведомления **в Telegram**
(T-134.4) о записях и напоминаниях, но в самом вебе/PWA системных push нет.

RuStore не требует push как условие публикации. Есть два пути:

| Вариант | Что даёт | Цена |
|---|---|---|
| **A. MVP без нативного push** (рекомендую) | In-app-уведомления + deep link в карточку/приём; напоминания остаются в Telegram, о чём честно сказано в витрине | минимум зависимостей и проверок модерации; пользователь без Telegram может не получить напоминание |
| **B. RuStore Push SDK уже в MVP** | Системные уведомления внутри приложения, недоступные без GMS | регистрация токена, разрешения, сервер отправки, дополнительная QA-матрица и риск модерации |

**Рекомендация:** первую публикацию делать по варианту A, а T-183
(RuStore Push SDK) не считать блокирующим релизом и перенести в Android
v1.1. Если вы хотите, чтобы приложение сразу было полноценным каналом
напоминаний — выбираем B и оставляем T-183 в Спринте 2. Нужно ваше
подтверждение.

### 7.4. Матрица устройств — что это

Матрица — конкретный список телефонов/версий Android/OEM-оболочек, на
которых проверяем установку из RuStore. Она нужна, потому что WebView, SSE
и фоновые режимы ведут себя по-разному: OEM-оболочки (Xiaomi/Honor)
агрессивно режут фоновую работу, а старые Android иначе рендерят CSS.

Предлагаемый минимум (T-188):

| Ось | Значения |
|---|---|
| Android | 10, 11, 12, 13, 14, 15 (эмулятор + хотя бы 2 реальных устройства) |
| Оболочки | Samsung OneUI, Xiaomi HyperOS/MIUI, Honor/Huawei без GMS, «чистый» Android |
| Экраны | телефон ~5.5", телефон ~6.7", планшет 10" |
| Локаль | русский интерфейс + английский, включённая тёмная тема |
| Сценарии | вход, SSE-чат, выбор питомца, карточка, история, deep link, обрыв сети |

Результат — чек-лист с версией сборки и скриншотами, приложенный к RC.

### 7.5. Бюджет на ассеты и краш-аналитику

**Ассеты (T-187):** по требованиям RuStore нужны иконка 512×512 и
минимум 3 скриншота на тип устройства. Базовый вариант — **ноль затрат**:
иконку делаем из существующего SVG-логотипа (`frontend/public/favicon.svg`),
скриншоты снимаем с работающего приложения на эмуляторе/телефоне в
нужном размере. Платный вариант — дизайнер (~5–15 тыс. ₽) и/или промо-видео
с VK Видео (необязательно).

**Краш-аналитика (T-188):** Google Crashlytics не подходит (нет GMS).
Варианты:

- **Ноль затрат:** self-hosted Sentry на уже арендованном VPS + отзывы и
  анкеты RuStore + логи API. Плюс — данные остаются у нас (152-ФЗ).
- **Платно:** Sentry SaaS (есть бесплатный лимит на старте) или другой
  аналог; проще поддержка, но данные у стороннего сервиса.

**Рекомендация:** начать с self-hosted Sentry и ручного сбора отзывов;
платный сервис подключить только если появятся crash-логи, которые
невозможно воспроизвести локально.

## 8. Definition of Done Android v1.0

- Сборка AAB/APK подписана, `versionName` совпадает с релизом API/веба.
- Установка с RuStore на устройства из матрицы; вход, чат, карточки, история,
  уведомления и deep links работают.
- Политика конфиденциальности и согласие 152-ФЗ доступны из приложения;
  удаление данных пользователя работает.
- CI собирает артефакт на каждый тег, GitHub Release содержит AAB/APK.
- RuStore-витрина заполнена, модерация пройдена, есть план отката и мониторинг.
- Документация обновлена: README, DEPLOYMENT, SECURITY, этот roadmap и TODO.
