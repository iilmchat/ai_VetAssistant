# Дорожная карта: Android-приложение и публикация в RuStore

**Дата:** 2026-11-19
**Статус:** планирование. Код Android-приложения ещё не написан.
**База:** прод VetAssistant **v1.14.2**, репозиторий `main`.
**Связанные задачи в TODO:** T-175…T-191 (спринты ниже), а также открытые
T-105, T-122, T-136, T-166, T-167.

## 1. Что есть сейчас (фактический аудит)

| Область | Состояние | Что мешает мобильному/RuStore |
|---|---|---|
| Веб-фронтенд | React 19 + Vite + TypeScript, SSE-чат, адаптивная вёрстка, тёмная/светлая тема, мобильный drawer (T-154), RU/EN (T-153), карточки питомцев (T-164) | Это **веб в браузере**, не Android-приложение. Нет `manifest.webmanifest`, service worker, иконок PWA, режима «установить на экран». |
| API | FastAPI, OpenAI-совместимый `/v1/chat/completions`, JWT, `/v1/patients`, `/v1/appointments`, `/v1/reminders`, Prometheus, graceful fallback | `CORS_ALLOWED_ORIGINS` в `app/main.py` содержит только `localhost:5173/3000`. Для WebView/TWA и мобильного origin нужно добавить `https://app.ai-pets.ru` (и при необходимости `android-app://...`). |
| Авторизация | JWT в `localStorage` браузера, логин/пароль, привязка Telegram | `localStorage` в WebView ненадёжен; нужен нативный безопасный ключ/хранилище. Открыта **T-105** (инвалидация JWT после смены пароля) — критично для мобильных долгоживущих сессий. |
| Память и пациенты (v1.14.x) | `patients`/`episodes`, pgvector `vector(384)`, `app/memory.py`, инструмент `create_patient`, agentic-инъекция | Функциональность доступна через API/веб; в нативном приложении нужно проверить SSE, выбор пациента и сохранение эпизодов в WebView. |
| Уведомления | Telegram-бот присылает напоминания о записях/напоминаниях (T-134.4) | Google FCM в RuStore-среде недоступен/нежелателен. Нужна интеграция **RuStore Push SDK** или явный fallback на Telegram. |
| Офлайн/надёжность | Нет офлайн-кэша. При обрыве SSE частичный ответ помечается ошибкой | Открыта **T-136** (докачка ответа). В мобильной сети обрывы частые — задача становится приоритетной. |
| Приватность | 152-ФЗ: в БД нет текстов диалогов, в `episodes` выжимки ≤ 500 символов, удаление каскадное | Открыта **T-166** (retention 180 дней). Для RuStore нужны политика конфиденциальности, согласие на обработку ПДн, удаление данных из приложения. |
| CI/CD | GitHub Actions: `ci.yml`, `release.yml`, `deploy.yml`; Docker-образы `api`/`frontend`; деплой на VPS по тегу | Нет Android-сборки, JDK/Gradle, keystore, подписи, AAB/APK-артефакта и загрузки в RuStore. Открыта **T-167** (грязное дерево на сервере). |
| Аккаунт и витрина RuStore | — | Нет аккаунта разработчика (VK ID), подписывающего ключа, иконок 512 px, скриншотов, описаний, возрастного рейтинга. |

**Вывод:** готово всё, что нужно для «умного агента» в браузере; для Android
не хватает оболочки, безопасной сессии, уведомлений, офлайн-режима и
полного цикла сборки/подписи/публикации.

## 2. Сравнение способов доставки

| Вариант | Суть | Плюсы | Минусы | Оценка |
|---|---|---|---|---|
| **PWA** | Манифест + service worker, «Добавить на главный экран» | минимум кода, нет магазина, мгновенные обновления | не публикуется в RuStore как приложение; уведомления и «нативный» вид ограничены | 1 спринт, как база для остальных |
| **TWA (Bubblewrap/Trusted Web Activity)** | APK, который открывает `https://app.ai-pets.ru` в Chrome Custom Tab | переиспользует весь веб, быстро; не нужен дубль UI | нужен `assetlinks.json` на домене; зависит от Chrome на устройстве; слабый доступ к нативным API (push, хранилище) | 1–2 спринта, запасной вариант |
| **Capacitor (рекомендуется)** | WebView-обёртка React-приложения + нативные плагины | один код UI; плагины для Secure Storage, Push, Deep Links, Filesystem; можно собрать AAB для RuStore | нужен Android SDK/Gradle, keystore, поддержка обновлений веб-ассетов | 3–4 спринта до витрины |
| **Kotlin Compose нативно** | Полностью отдельный UI | максимум возможностей и производительности | дублирование UI/логики, дорого и медленно | не сейчас |

**Рекомендация:** сначала PWA-база (быстрый выигрыш и меньше риска), затем
Capacitor как основной путь в RuStore; TWA держать как fallback, если
Capacitor упрётся в модерацию или сроки. Kotlin — отдельная инициатива после
продуктовой проверки гипотезы.

## 3. Требования RuStore (проверить актуальные значения перед релизом)

Официальная документация: <https://help.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication>,
консоль разработчика: <https://www.rustore.ru/developer> (вход через VK ID).
На дату планирования учитываем:

- [ ] Аккаунт разработчика RuStore (VK ID), подтверждённые данные, роль
      пользователя с правом публикации.
- [ ] Подпись приложения собственным keystore; ключ и пароль хранятся в
      секретах CI, не в репозитории; продуман план ротации.
- [ ] Сборка в формате, который требует Консоль на момент загрузки
      (APK/AAB — уточнить в Консоли); 64-bit нативные библиотеки;
      `targetSdk`/`minSdk` по актуальным требованиям сезона — **обязательно
      перепроверить перед первым билдом**.
- [ ] Иконка 512×512, набор скриншотов, короткое/полное описание на русском,
      категория, контакт поддержки, версия и `versionCode`, возрастной рейтинг.
- [ ] Политика конфиденциальности и условия использования (можно
      переиспользовать `landing/privacy/` и `landing/terms/`, проверить
      актуальность и добавить пункты про patient cards/эпизоды).
- [ ] Возрастной рейтинг и анкета содержимого; для медицинского ассистента —
      явный дисклеймер «не заменяет осмотр врача», без дозировок и диагнозов.
- [ ] Данные и разрешения: Explain & consent для 152-ФЗ, удаление данных из
      приложения, отказ от Google Play Services/зависимостей GMS; при
      необходимости — RuStore SDK (push/обновления/аналитика).
- [ ] Первую публикацию делать через тестовый/внутренний круг, перед
      релизом зафиксировать план отката (снятие публикации/новая версия).

## 4. Спринты и задачи

Спринт = 2 недели, кроме нулевого (1 неделя). Номера T-175…T-191 зарезервированы
в `TODO.md`.

### Спринт 0 (1 неделя) — решение и фундамент

- **T-175.** Финальный аудит RuStore и выбор модели доставки. Результат:
  утверждённый Capacitor (TWA — fallback), таблица требований, сроки, владельцы.
- **T-176.** PWA-база: `manifest.webmanifest`, иконки, service worker
  (offline-shell), `display: standalone`, meta, install-подсказка. Выход:
  приложение ставится на экран Android из браузера.
- **T-177.** Мобильная готовность API: добавить `https://app.ai-pets.ru`
  (и при TWA `android-app://...`) в `CORS_ALLOWED_ORIGINS`; зафиксировать
  `VITE_API_BASE_URL`; документировать прокси/HTTPS.
- **T-178.** Базовый QA-прогон в мобильных браузерах (Chrome Android 10–15,
  OEM-оболочки): чат/SSE, карточки, тема, RU/EN, клавиатура, safe-area.
  Выход: список дефектов и метрики до мобильного релиза.

### Спринт 1 (2 недели) — MVP Android-обёртки

- **T-179.** Capacitor-проект: `capacitor.config.ts`, `android/`, скрипты
  `npm run android:build` / `:sync` / `:open`, README по локальной сборке.
- **T-180.** Нативная оболочка: splash, иконки, статус-бар под тему, safe-area,
  обработка системной «Назад», ориентация, без «canvas-пикселей» и зум-багов.
- **T-181.** Сессия и данные: безопасное хранилище токена вместо
  `localStorage`; автологин/logout; проверка чата, SSE, patient picker,
  карточки и истории эпизодов внутри WebView. Зависит от T-105.
- **T-182.** Подпись и сборка: keystore в секретах, `versionCode/versionName`,
  release AAB/APK, GitHub Actions job `Android Build`, артефакт на GitHub

### Спринт 2 (2 недели) — уведомления, ссылки, офлайн

- **T-183.** Уведомления: RuStore Push SDK (приоритет) либо fallback на
  Telegram-уведомления; deep-link из уведомления в карточку/приём.
- **T-184.** Deep links: `vetassistant://patient/{id}` и/или App Links
  `https://app.ai-pets.ru/...`; `assetlinks.json` при TWA/App Links;

- **T-185.** Офлайн-деградация: кэш последних диалогов/карточек, понятные

- **T-187.** Витрина: аккаунт разработчика, имя приложения, категория,

| Задача | Почему важна для Android |

## 6. Риски и меры

| Риск | Мера |
|---|---|
| Зависимость от Google services | RuStore Push SDK / Telegram fallback; не использовать FCM как единственный канал |
| Устаревшие требования RuStore (SDK/target API) | проверка Консоли на старте каждого спринта; фиксация версий в T-175/T-189 |
| Потеря keystore | хранение в секретах CI + бумажная/офлайн-копия у владельца; план ротации |
| WebView рвёт SSE/фоновую работу | T-136 + тесты обрывов; честные состояния в UI |
| Модерация медицинской тематики | дисклеймеры, без дозировок, возрастной рейтинг, политика данных |
| Утечка ПДн через локальный кэш | безопасное хранилище, шифрование где возможно, кнопка «удалить данные» |
| Расхождение версий веба и обёртки | `versionName` = версия веб-релиза; обновление ассетов через CI; smoke-тест после деплоя |

## 8. Definition of Done Android v1.0

- Сборка AAB/APK подписана, `versionName` совпадает с релизом API/веба.
- Установка с RuStore на устройства из матрицы; вход, чат, карточки, история,
  уведомления и deep links работают.
- Политика конфиденциальности и согласие 152-ФЗ доступны из приложения;
  удаление данных пользователя работает.
- CI собирает артефакт на каждый тег, GitHub Release содержит AAB/APK.
- RuStore-витрина заполнена, модерация пройдена, есть план отката и мониторинг.
- Документация обновлена: README, DEPLOYMENT, SECURITY, этот roadmap и TODO.
