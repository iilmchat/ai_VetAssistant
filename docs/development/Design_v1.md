# Design: Русскоязычный ветеринарный ассистент (v1)

**Статус:** draft для обсуждения
**Принятые решения:** основное облако — зарубежное (Vast.ai/RunPod через посредника), учитель для синтетики — зарубежная API-модель через российский агрегатор. Российское GPU-облако и российский API — **резервный контур**, заложенный в архитектуру как переключаемый провайдер, а не как отдельная ветка разработки.

---

## 1. Цели и рамки

**Цель v1:** получить GGUF-модель Qwen3-8B, дообученную на русскоязычных ветеринарных диалогах, которая на CPU-лаптопе без GPU ведёт многотурный диалог с владельцем животного, соблюдает рамки безопасности и проходит внутренний бенчмарк.

**В scope:**
- многотурный чат (приоритет), одиночные ответы, блок безопасности;
- синтетические данные + перевод PetQA + сиды из MSD Vet Manual;
- QLoRA-SFT → merge → GGUF Q4_K_M / Q5_K_M;
- внутренний русский вет-бенчмарк (200–300 вопросов);
- CPU-инференс как целевой сценарий.

**Вне scope v1 (но заложено в дизайн):**
- function calling (запись к приёму, напоминания) — этап 2 вместе с DPO;
- RAG по справочникам, мультимодальность (фото животного), полное дообучение, серверный GPU-инференс.

**Ключевой принцип дизайна — provider abstraction.** Всё, что зависит от провайдера (облако, API учителя, хранилище), выносится за интерфейс, чтобы переключение «зарубеж → РФ» было сменой конфига, а не переписыванием пайплайна. Это прямое следствие вашего решения держать РФ-контур запасным.

## 3. Данные

### 3.1 Схема (JSONL, ChatML messages)

```json
{
  "id": "vet-mt-000123",
  "source": "synthetic_petqa_seed",
  "topic": "gastroenterology",
  "language": "ru",
  "type": "multi_turn",
  "messages": [
    {"role": "system", "content": "Ты — ветеринарный ассистент..."},
    {"role": "user", "content": "У кота третий день понос, он вялый..."},
    {"role": "assistant", "content": "Уточните, пожалуйста: ..."},
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."}
  ],
  "meta": {
    "turns": 4,
    "safety_flagged": false,
    "vet_reviewed": false,
    "seed_ref": "petqa:ko:004512"
  }
}
```

Типы записей в датасете v1:
| Тип | Доля | Назначение |
|---|---|---|
| `multi_turn` | ~60% | основной сценарий, 3–6 реплик |
| `single_turn` | ~25% | одиночные вопросы, factuality |
| `safety` | ~15% | отказ от диагноза, эскалация к врачу, осторожность с дозировками, «недостаточно контекста» |

Целевой объём v1: **8–12k примеров**.

### 3.2 Пайплайн генерации

1. **Seed pool.** MSD Vet Manual (открытый справочник) → извлечение фактов по таксономии тем; переведённые вопросы PetQA (10 076 текстовых QA, корейский → русский); ручная таксономия (~20 тем: ЖКТ, дерматология, поведение, экстренные состояния и т.д.).
2. **Генерация в два шага.** (а) из факта/вопроса генерируется реалистичный вопрос владельца; (б) генерируется многотурный диалог, где ассистент **обязательно задаёт уточняющие вопросы** перед рекомендацией. Промпты — в отдельной библиотеке с версионированием.
3. **Фильтрация.** Дедупликация (MinHash/embeddings), языковой фильтр (ru), проверка длины, классификатор безопасности (флагует категоричные диагнозы и дозировки), проверка отсутствия PII.
4. **Ветеринарная вычитка.** 10–15% стратифицированной выборки — живым ветеринаром; результаты вычитки используются для калибровки промптов и фильтров, а не для ручной правки всего датасета.

### 3.3 Слой абстракции учителя

Интерфейс — OpenAI-совместимый (`base_url` + `api_key` + `model`). Реализации:

| Провайдер | Роль | Переключение |
|---|---|---|
| Российский агрегатор (GPT/Claude/Gemini) | **primary** | конфиг |
| GigaChat / YandexGPT | fallback | конфиг |
| Открытая модель в своём контуре | резерв при блокировках | конфиг + GPU |

Один и тот же промпт-сет прогоняется через primary и fallback на пилотном батче (200–300 диалогов), сравнение по качеству/цене — это отдельный gate перед масштабированием генерации.

## 4. Обучение

**Стек:** Unsloth (2× быстрее и до −70% VRAM против стандартного QLoRA) → Qwen3-8B, 4-bit.

```yaml
# training config (draft)
base_model: Qwen/Qwen3-8B
method: qlora
load_in_4bit: true
lora:
  r: 16
  alpha: 32
  dropout: 0.05
  target_modules: all-linear
training:
  epochs: 2
  lr: 2.0e-4
  lr_scheduler: cosine
  warmup_ratio: 0.03
  per_device_batch_size: 2
  grad_accum: 8          # effective batch 16
  max_seq_len: 4096      # 8192 при длинных многотурных
  bf16: true
  neftune_alpha: 5
  packing: false         # для многотурных лучше без packing
template: chatml
```

**Требования к GPU:** 24 ГБ VRAM достаточно (RTX 4090). Один полный прогон — ~10–20 ч, стоимость **$7–20** в зависимости от площадки.

**Обёртка:** Docker-образ с тренировочным скриптом и конфигом. Образ не зависит от провайдера — запускается на Vast.ai/RunPod (primary) или в РФ-облаке (fallback) без изменений.

**Версионирование:** конфиг + датасет-хеш + git-коммит → ID прогона; артефакты (adapter, merged model, логи) складываются в хранилище с этим ID.

---

## 5. Экспорт и деплой

1. Merge LoRA → HF (bf16).
2. `llama.cpp` convert → GGUF.
3. Квантование: **Q4_K_M** (основной) + **Q5_K_M** (для машин с 16+ ГБ RAM).
4. Валидация: токенизатор, sanity-прогон на 20 промптах, замер **ток/с на целевом лаптопе** (критерий приёмки — ≥8 ток/с для 8B Q4_K_M).
5. Артефакты поставки: GGUF-файлы, карточка модели (что умеет/не умеет, ограничения, безопасность), инструкция запуска (llama.cpp / Ollama), примеры промптов.

## 6. Оценка

**Бенчмарк:** 200–300 вопросов на русском.
- **MCQ (знания)** — часть адаптируется из PetQA-Bench (русской версии нет — это наша новизна), часть пишется под таксономию.
- **Open-ended reasoning** — оценка LLM-judge + ветеринарная выборочная проверка.
- **Safety** — корректность отказа/эскалации, отсутствие категоричных диагнозов и дозировок без оговорок.
- **Multi-turn** — удержание контекста, качество уточняющих вопросов, отсутствие противоречий между турами.

**Пороги приёмки v1** (по образцу рамок коммерческих вет-ассистентов):

| Метрика | Порог |
|---|---|
| MCQ accuracy | ≥ 80% |
| Reasoning (LLM-judge + вет) | ≥ 75% |
| Safety pass rate | 100% критических кейсов без провала |
| Multi-turn consistency | ≥ 80% |
| Скорость на целевом CPU | ≥ 8 ток/с (8B Q4_K_M) |

Сравнение всегда с **base Qwen3-8B** на том же бенчмарке — иначе не видно, что дал файнтюн.

## 7. Инфраструктура и бюджет

| Компонент | Primary | Fallback |
|---|---|---|
| Обучение | Vast.ai (4090, ~$0.27–0.43/ч) / RunPod | Selectel / T1 (L40S) / MWS |
| Генерация синтетики | Зарубежный API через РФ-агрегатор | GigaChat / YandexGPT |
| Хранилище артефактов | S3-совместимое (выбор — по объёму) | РФ-облако |
| Оплата | Посредник / карта инобанка | Рублёвый договор |

**Бюджет на месяц активных экспериментов:** $200–450 (облако) + наценка посредника 10–30% + API-генерация (оценивается после пилотного батча).

## 8. Риски и митигации

| Риск | Вероятность | Митигация |
|---|---|---|
| Блокировка/потеря доступа к зарубежному облаку или API | средняя | provider abstraction + заранее протестированный РФ-fallback (один прогон на L40S до того, как он понадобится) |
| Платежи через посредника (деньги на балансе) | средняя | не держать большой баланс, пополнять под прогон |
| Качество синтетики на русском | средняя | пилотный батч + сравнение primary/fallback + ветеринарная вычитка |
| Галлюцинации/небезопасные советы | высокая для домена | safety-блок в данных, пороги приёмки, дисклеймер в system prompt, эскалация к врачу |
| 152-ФЗ / PII | низкая при синтетике | только синтетика и деперсонифицированный PetQA, PII-фильтр в пайплайне |
| Переобучение на домене | средняя | 1–2 эпохи, early stopping по val, сравнение с base |

## 9. Дорожная карта

| Этап | Выход | Gate |
|---|---|---|
| **0. Инфра** | Docker-образ обучения, аккаунты, тестовый прогон на 100 примерах | прогон завершается, артефакты сохраняются |
| **1. Данные v1** | 8–12k JSONL, пилот primary vs fallback учителя | качество пилота приемлемо, ветеринар посмотрел выборку |
| **2. SFT** | LoRA adapter + merged HF | val loss не растёт, нет коллапса |
| **3. Eval** | отчёт по бенчмарку vs base | пороги раздела 6 |
| **4. GGUF + деплой** | Q4_K_M / Q5_K_M + карточка + инструкция | ≥8 ток/с на целевом лаптопе |
| **5. Итерация 2** | DPO + function calling | отдельный дизайн-ревью |

## 10. Открытые вопросы

1. **Ветеринар-консультант** — кто и на каких условиях? Это gate для этапов 1 и 3; без него качество не гарантировать.
2. **Агрегатор API** — какой конкретно? Нужно проверить доступность нужных моделей, лимиты и цену до старта генерации.
3. **Целевой объём многотурных** — 60% от 8–12k достаточно для v1, или сразу целимся в 15k+?
4. **Хранилище артефактов** — РФ-облако с первого дня (проще с юрлицами позже) или зарубежное S3 на старте?
5. **Лицензия и поставка** — GGUF будет распространяться внутри или публично? От этого зависит, какие ограничения Qwen3-лицензии и PetQA нужно проверить.
