# RULES.md: Правила разработки VetAssistant

Этот документ описывает стандарты кода, коммитов и отчетности для агента OpenCode. Нарушение правил — блокер для мержа.

## 1. Принципы
- **Безопасность превыше всего.** В ветеринарном домене не бывает «почти правильных» ответов. Все safety-фильтры должны работать.
- **Только синтетика и деперсонифицированные данные.** Никаких реальных имен, адресов или телефонов в датасете (152-ФЗ).
- **Провайдер-агностицизм.** Код не должен быть жестко привязан к Vast.ai или конкретному API. Всё через конфиги (`.env`).
- **Строгая типизация.** В Python используем `mypy --strict`, в TypeScript — `strict: true`.

## 2. Ветвление и коммиты
- Ветки: `feat/T-NNN-<slug>`, `fix/KI-NNN-<slug>`.
- Коммиты — по Conventional Commits (например, `feat(data): add stage A prompt parser (T-005)`).

## 3. Код
- **Python 3.11+**.
- **Стиль:** `ruff` с `line-length = 100`.
- **Конфиги:** только через `pydantic-settings` и `.env`. Никакого `os.getenv` напрямую.
- **Скрипты:** каждый скрипт в папке `scripts/` должен иметь `--help` и `--dry-run`.
- **Логирование:** использовать `loguru` или `structlog`, никаких `print()`.

## 4. Данные и тесты
- Тестов на генерацию данных нет, но есть **валидаторы**. Каждый сгенерированный диалог обязан проходить JSON-схему (через Pydantic).
- Тесты кода (pytest) обязательны для утилит парсинга и фильтрации. Покрытие ядра — не ниже 80%.
- Все секреты (API-ключи) — только в `.env` (добавлен в `.gitignore`).

## 5. Документация
- Источник истины по архитектуре — `Design.md`.
- Источник истины по задачам — `TODO.md`.
- Если в ходе работы выясняется, что промпт в `synthetic_prompts.md` не работает, агент должен предложить правку, но не менять его молча.

## 6. Блокеры
Если API не отвечает или возникает ошибка в пайплайне:
1. Остановиться.
2. Записать ошибку в лог.
3. Сообщить Архитектору (мне) в чат: `⚠️ Блокер в задаче T-NNN: <описание>`.

## 7. Формат отчета по задаче (СТРОГО)
После каждого закрытого пункта из TODO.md агент выдает отчет из 5 пунктов:
1. **Файлы:** какие созданы/изменены (список путей).
2. **Что сделано:** краткое описание.
3. **Тесты/Проверки:** какие команды запущены и их вывод (например, `pytest: 5 passed`).
4. **Проблемы:** если были блокеры, как обошли (или не обошли).
5. **Следующий шаг:** ссылка на следующий T-NNN.
