# RAG_EVAL — hit rate расширенной базы знаний (T-133)

**Дата прогона:** 2026-11-05  
**Версия:** v1.5.6  
**Окружение:** production edge-стек (`app.ai-pets.ru`), CPU-инференс  
**Коллекция:** `msd_vet_manual`, **766 чанков** (было 204 до T-133)  
**Новые статьи:** 10 (ксилит, парвовирус, эпилепсия, виноград/изюм, антифриз,
панкреатит, дирофиляриоз, чумка, CPR, лейкоз кошек)  
**Скрипт:** `scripts/evaluate_rag.py`  
**Модель:** `qwen3-8b-vet` (GGUF Q4_K_M)

## 1. Методика

1. 12 вопросов — по два на каждую из шести тем расширения. Каждый вопрос
   отправляется в `POST /v1/chat/completions` с `use_rag: true`,
   `temperature: 0.2`, `max_tokens: 600`, `stream: false` (только так API
   отдаёт точный `usage` с токенами).
2. Перед каждым вопросом и сразу после него считывается счётчик
   `vet_rag_searches_total{result="hit"|"miss"}` из `/metrics` контейнера API
   (`--metrics-url`) либо из Prometheus (`--prometheus-url`).
3. Вопрос считается **RAG hit**, если прирост `hit` за время запроса ≥ 1.
   Если прирост не наблюдался, но вырос `miss` — **RAG miss**.
   При `hit + miss > 1` скрипт пишет предупреждение о фоновом трафике.
4. Дополнительно фиксируются ключевые основы факта в ответе
   (`гипогли`, `печен`, `почк`, `фомепизол`, …) — вспомогательная проверка,
   что чанки действительно повлияли на ответ.

Команда прогона (внутри контейнера API на сервере):

```bash
docker compose -f docker-compose.edge.yml exec api \
  python scripts/evaluate_rag.py \
    --api-url http://127.0.0.1:8000 \
    --email owner@example.com \
    --metrics-url http://127.0.0.1:8000/metrics \
    --output /app/data/rag_eval_results.json \
    --markdown-out /app/data/rag_eval_table.md
```

- **100 % hit rate** на всех 12 вопросах: новые статьи действительно
  индексируются и попадают в контекст ответа.
- Индекс вырос с 204 до 766 чанков (×3.75) без потери старых материалов.
- Среднее время ответа 74.6 с на CPU (Q4_K_M, 8B) — ожидаемо для полного
  ответа без стриминга; в UI пользователи получают ответ потоком.
- Счётчик `vet_rag_searches_total` глобальный, поэтому прогон выполнялся в
  отсутствие пользовательского трафика; при фоновых запросах скрипт
  предупреждает о дельте больше 1.
- `llama-cpp-python` не отдаёт `usage` в стриме, поэтому оценка шла
  нестриминговыми запросами — токены точные.
