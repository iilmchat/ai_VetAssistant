# RAG_EVAL — hit rate расширенной базы знаний (T-133)

**Дата прогона:** 2026-11-05
**Версия:** v1.5.6
**Окружение:** production edge-стек (`app.ai-pets.ru`), CPU-инференс
**Коллекция:** `msd_vet_manual`, **766 чанков** (было 204 до T-133)
**Новые статьи:** 10 (ксилит, парвовирус, эпилепсия, виноград/изюм, антифриз,
панкреатит, дирофиляриоз, чумка, CPR, лейкоз кошек)
**Скрипт:** `scripts/evaluate_rag.py`
**Модель:** `qwen3-8b-vet` (GGUF Q4_K_M)

## 1. Методика

1. 12 вопросов — по два на каждую из шести тем расширения. Каждый вопрос
   отправляется в `POST /v1/chat/completions` с `use_rag: true`,
   `temperature: 0.2`, `max_tokens: 600`, `stream: false` (только так API
   отдаёт точный `usage` с токенами).
2. Перед каждым вопросом и сразу после него считывается счётчик
   `vet_rag_searches_total{result="hit"|"miss"}` из `/metrics` контейнера API
   (`--metrics-url`) либо из Prometheus (`--prometheus-url`).
3. Вопрос считается **RAG hit**, если прирост `hit` за время запроса ≥ 1.
   Если прирост не наблюдался, но вырос `miss` — **RAG miss**.
   При `hit + miss > 1` скрипт пишет предупреждение о фоновом трафике.
4. Дополнительно фиксируются ключевые основы факта в ответе
   (`гипогли`, `печен`, `почк`, `фомепизол`, …) — вспомогательная проверка,
   что чанки действительно повлияли на ответ.

Команда прогона (внутри контейнера API на сервере):

```bash
docker compose -f docker-compose.edge.yml exec api \
  python scripts/evaluate_rag.py \
    --api-url http://127.0.0.1:8000 \
    --email owner@example.com \
    --metrics-url http://127.0.0.1:8000/metrics \
    --output /app/data/rag_eval_results.json \
    --markdown-out /app/data/rag_eval_table.md
```

## 8. T-141 — гибридный поиск (BM25 + векторы)

**Дата офлайн-замера:** 2026-11-06.
**Корпус:** 766 чанков из `data/knowledge/` (20 файлов, включая 17 статей
MSD на английском).
**Скрипт:** `scripts/evaluate_hybrid_rag.py --mode bm25`.
**Метрика:** попала ли ожидаемая статья в top-3 **поиска** (не ответа модели).

### 8.1. Ограничение корпуса

Статьи MSD Vet Manual англоязычные, вопросы пользователей — русские. Поэтому
«чистый» BM25 по русскому запросу не находит нужную статью: слова `ксилит`
в английском тексте нет. Три русских демо-файла (`diarrhea_dogs.txt`,
`paracetamol_cats.txt`, `seizures_emergency.txt`) наоборот совпадают
буквально и перетягивают top-3 на себя.

Решение T-141: русско-английский глоссарий `RU_EN_TERMS` в
`app/rag_hybrid.py` + понижение веса русских токенов до 0.25, когда для них
нашёлся перевод. BM25 при этом остаётся стандартным Okapi BM25.

### 8.2. Результаты BM25 (офлайн, 17 вопросов)

| Режим | Hit@3 | Hit rate | MRR | Среднее, мс | p95, мс |
|---|---:|---:|---:|---:|---:|
| BM25 без глоссария (`--no-expand`) | 0/17 | **0 %** | 0.000 | 0.6 | 1.2 |
| BM25 + глоссарий + вес RU 0.25 | **17/17** | **100 %** | **0.931** | 2.1 | **3.6** |

Целевой p95 поиска — не выше 100 мс: фактически 3.6 мс на 766 чанках, бюджет
не расходуется. Без глоссария лексический канал бесполезен — это и есть
причина, по которой наивный BM25 в этом проекте не дал бы прироста.

### 8.4. Что ещё не измерено

Офлайн-замер покрывает только лексический канал: в локальном окружении нет
`chromadb` и `sentence-transformers`, поэтому vector-only и hybrid на
реальном индексе здесь не запускались. Answer-level hit rate 100 % из §2 —
другая метрика (счётчик `vet_rag_searches_total`), она не заменяет
retrieval-level.

Серверный прогон (после пересборки индекса с `title` и рестарта API):

```bash
docker compose -f docker-compose.edge.yml run --rm --no-deps \
  --entrypoint python api scripts/evaluate_hybrid_rag.py --mode both \
  --output /app/data/rag_hybrid_eval_results.json
```

Критерии приёмки T-141:

1. hybrid hit rate@3 не ниже vector-only на тех же 17 вопросах;
2. препаратные вопросы (13–17) в hybrid — rank 1 или 2;
3. p95 поиска hybrid не выше vector + 100 мс;
4. если hybrid просел — `VET_API_RAG_BM25_WEIGHT=0.5` (или 0.3), повторить
   замер; `VET_API_RAG_MODE=vector` остаётся полным откатом.

### 8.5. Вывод

Лексический канал с глоссарием закрывает главный риск T-141: на 17
контрольных вопросах BM25 сам находит нужную статью в top-3 в 100 % случаев
(без глоссария — 0 %). Осталось подтвердить, что слияние RRF не вытесняет
векторные хиты на сервере; до этого прод остаётся на текущей версии, а
default `hybrid` включается только вместе с релизом v1.7.0.
