# RAG_EVAL — hit rate расширенной базы знаний (T-133)

**Дата:** _заполнить после прогона_  
**Версия:** v1.5.6  
**Коллекция:** `msd_vet_manual`, **766 чанков** (было 204 до T-133)  
**Новые статьи:** 10 (ксилит, парвовирус, эпилепсия, виноград/изюм, антифриз,
панкреатит, дирофиляриоз, чумка, CPR, лейкоз кошек)  
**Скрипт:** `scripts/evaluate_rag.py`  
**Модель:** `qwen3-8b-vet` (GGUF Q4_K_M, CPU)

## 1. Методика

1. 12 вопросов — по два на каждую из шести тем расширения (итого 12 запросов
   к `/v1/chat/completions` с `use_rag: true`, `temperature: 0.2`,
   `max_tokens: 600`).
2. Перед каждым вопросом и сразу после него считывается счётчик
   `vet_rag_searches_total{result="hit"|"miss"}`:
   - из `/metrics` контейнера API (`--metrics-url`), либо
   - из Prometheus (`--prometheus-url`).
3. Вопрос считается **RAG hit**, если прирост `hit` за время запроса ≥ 1.
   Если прирост не наблюдался, но вырос `miss` — **RAG miss**.
   При `hit + miss > 1` в лог пишется предупреждение о фоновом трафике.
4. Дополнительно фиксируются ключевые основы факта в ответе
   (`гипогли`, `печен`, `почк`, `фомепизол`, …) — это не метрика, а
   вспомогательная проверка, что чанки действительно повлияли на ответ.

Команда прогона (внутри контейнера API на сервере):

```bash
docker compose -f docker-compose.edge.yml exec api \
  python scripts/evaluate_rag.py \
    --api-url http://127.0.0.1:8000 \
    --email owner@example.com \
    --metrics-url http://127.0.0.1:8000/metrics \
    --markdown-out /tmp/rag_eval_table.md
```

Через Prometheus (если `exec api` недоступен):

```bash
python scripts/evaluate_rag.py \
  --api-url https://app.ai-pets.ru/api \
  --prometheus-url http://vetassistant-prometheus:9090 \
  --token "$VET_EVAL_TOKEN"
```

Без `--metrics-url`/`--prometheus-url` скрипт соберёт ответы, но hit будет `n/a`.

## 5. Наблюдения и ограничения

- Счётчик `vet_rag_searches_total` глобальный: при фоновом трафике дельта
  может быть больше 1 — скрипт предупреждает об этом.
- `llama-cpp-python` не отдаёт `usage` в стриме, поэтому прогон идёт
  нестриминговыми запросами (`stream: false`) — токены точные.
- Совпадение ключевых основ — эвристика; итоговый hit определяется
  счётчиком, а не текстом ответа.
- Если Prometheus недоступен, hit rate не измеряется — используйте
  `--metrics-url` из контейнера API.
