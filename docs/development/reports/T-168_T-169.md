## T-169 — `create_patient` не инжектился на «создай карточку»

### 1. Файлы

- `app/main.py` — `_PATIENT_CREATION_PATTERN`, `_requests_patient_creation`,
  `_mentions_pet`, `_effective_tools`.
- `app/tools.py` — описание `CREATE_PATIENT_TOOL`, `build_tools_instruction`.
- `tests/test_patient_tools.py` — +24 теста (фразы, отрицательные кейсы,
  приоритеты, API-сценарий).

### 2. Что сделано

**Причина.** В v1.14.0 `_effective_tools` добавлял `create_patient` только
при маркерах из `_PET_CONTEXT_CUES` («у меня», «мой», «зовут», «питом»…).
Фраза «Создай карточку Мурзика» не содержала ни одного маркера, поэтому
модель получала только клиентские `book_appointment` и `set_reminder` и
вызывала `book_appointment`.

**Исправление.**

1. Добавлена регулярка `_PATIENT_CREATION_PATTERN`, которая ловит:
   - «создай/создайте/создать … карточку»;
   - «создай/создайте/создать … питомца»;
   - «добавь/добавьте/добавить … питомца»;
   - «заведи/заведите/завести … карточку»;
   - «новая/новую/новой карточка»;
   - английские `create patient`, `create pet`, `add pet`.
2. `_requests_patient_creation` вызывается до эвристики «рассказывает о
   питомце». При явной просьбе `create_patient` добавляется **всегда**:
   - если `patient_id` уже выбран (создаём новую карточку);
   - если `use_patient_tools=false` (явное действие пользователя важнее
     автоинъекции);
   - если клиент прислал другие инструменты (они сохраняются, дубликата
     `create_patient` нет).
3. Описание инструмента и системная инструкция теперь явно говорят:
   «создай карточку» — это `create_patient`, **а не** `book_appointment`.

Локальное окружение Python 3.12 не содержало `pytest`/`openai`/`httpx2`/

5.0.0, несовместимый с `passlib`). На код релиза это не влияет — CI
использует чистую установку.

## T-168 — вёрстка сайдбара и поля ввода

### 1. Файлы

- `frontend/src/components/Toggle.tsx` — flex-позиционирование knob.
- `frontend/src/components/Composer.tsx` — `noValidate`, зелёный фокус,
  подавление `:invalid`.
- `frontend/src/index.css` — правила `.composer-input:invalid` /
  `:user-invalid` / `:focus`.

### 2. Что сделано

**Причина переключателей.** Knob был `absolute` без `left`, поэтому его
static position вычислялся браузером внутри кнопки, а сверху применялся
`translate-x-[18px]`. Замер через CDP: кнопка `x=258…294`, knob
`x=294…310` — суммарный сдвиг 36 px вместо 18 px, правый край выходил за
карточку. На узком сайдбаре это обрезало переключатель и текст.

**Исправление.** Кнопка стала flex-контейнером (`flex items-center p-0.5`),
knob — обычный flex-элемент `16×16` с `translate-x-0` / `translate-x-4`.
Никакого absolute и magic-числа 18: checked — `2 + 16 = 18 px`, справа
остаётся 2 px; unchecked — 2 px слева.

**Причина красной обводки.** Нативная валидация формы и браузерные стили
`:invalid`/`:user-invalid` перекрывали декоративный border контейнера.
**Исправление:** `noValidate` у формы, `border-0`/`shadow-none` у textarea,
CSS-правила для `:invalid`/`:user-invalid` и усиленный зелёный
`focus-within` (`border-emerald-500/60`, `ring-2 ring-emerald-500/25`).

`node_modules` был установлен частично (отсутствовали `react-i18next`,
`i18next`), из-за чего первый `npm run build` падал на типах. Выполнен
`npm ci` по `package-lock.json`; после этого lint/test/build чистые.
